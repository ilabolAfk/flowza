# Flowza

Локальный визуальный конструктор автоматизаций: собираешь сценарий из нод на канвасе
в браузере, запускаешь и смотришь результат по каждой ноде.

Работает целиком на своей машине: Flask отдаёт редактор на `127.0.0.1`, граф хранится
в JSON-файле, наружу ничего не уходит, кроме явно настроенных нод «Вебхук» и «Письмо».

## Запуск

```bash
pip install -r requirements.txt
python main.py                # откроет браузер на http://127.0.0.1:8765
python main.py --port 8800 --no-browser
```

`run.bat` делает то же самое для Windows. Сборка в один exe:

```bash
pyinstaller Flowza.spec
```

## Портативная сборка

`dist\Flowza.exe` — один файл, всё внутри: интерпретатор Python, Flask,
Werkzeug, Jinja2, `VCRUNTIME140.dll`, статика и шрифт иконок. Python и Flask
на машине не нужны.

```bash
pyinstaller Flowza.spec          # dist\Flowza.exe (~16 МБ)
```

Для переноса на другой ПК: `dist\Flowza-portable-windows.zip` (exe + инструкция).
Проверено запуском с `PATH=C:\Windows\System32;C:\Windows` — без системного
Python приложение поднимается и выполняет граф.

Важно: граф сохраняется в `Документы\Flowza`, а не рядом с exe; путь
переопределяется переменной `FLOWZA_GRAPH`.

## Сборка под Linux

PyInstaller не умеет кросс-компиляцию: ELF-бинарник собирается только на Linux.
Скрипт делает это в контейнере:

```bash
./build_linux.sh                 # нужен Docker
```

Получается `dist/Flowza` (ELF, Debian 12 / glibc 2.36+). Архив для переноса —
`dist/Flowza-portable-linux.tar.gz`: бинарник, инструкция, `flowza.desktop` и
`flowza.png` для меню.

```bash
tar -xzf Flowza-portable-linux.tar.gz
cd Flowza-linux && chmod +x Flowza && ./Flowza
```

На Linux данные лежат в `~/.local/share/flowza` (или `$XDG_DATA_HOME/flowza`).
Иконка в меню ставится файлом `flowza.desktop` — команды есть в инструкции
внутри архива.

Проверка собранного бинарника:

```bash
docker run --rm -v "$PWD:/src" -w /src/dist python:3.11-slim-bookworm bash -lc \
  'tar -xzf Flowza-portable-linux.tar.gz -C /tmp && cd /tmp/Flowza-linux && \
   ./Flowza --no-browser --port 8796 & sleep 12; python3 /src/packaging/verify_linux.py'
```


## Где лежит граф

| Запуск | Путь |
| --- | --- |
| из исходников | `flowza_graph.json` рядом с проектом |
| собранный exe | `Документы\Flowza\flowza_graph.json` |
| собранный бинарник Linux | `~/.local/share/flowza/flowza_graph.json` |
| переменная окружения | `FLOWZA_GRAPH=/полный/путь/файл.json` |

Сохранение — кнопка «Сохранить» или `Ctrl+S`. Кнопка «Открыть» перечитывает файл с диска.

## Горячие клавиши

| Клавиша | Действие |
| --- | --- |
| `F5` | запустить граф |
| `Ctrl+S` | сохранить |
| `Ctrl+O` | перечитать файл |
| `Ctrl+N` | новый граф |
| `Ctrl+Z` / `Ctrl+Y` | отменить / повторить |
| `Ctrl+L` | автораскладка |
| `Delete` | удалить выбранные ноды |
| колесо | зум, ЛКМ по фону или пробел+ЛКМ — панорама |

Клик по ребру открывает над линией кнопку «Удалить связь»; клик по пустому месту
или `Esc` закрывает её. Удаление отменяется через `Ctrl+Z`. Клавиша `Delete`
при открытой плашке тоже удаляет связь.

## Ноды

25 нод в шести группах:

- **Источники**: ручной запуск, расписание, вебхук (вход), ввод JSON, HTTP GET.
- **Логика**: условие, фильтр, объединение, задержка.
- **Данные**: карта полей, вычисление поля, переименование, склейка строк,
  цикл по элементам, агрегация, регулярное выражение, дата и время.
- **Файлы и БД**: прочитать файл, записать файл, запрос к SQLite.
- **Действия**: письмо (SMTP), вебхук (HTTP), журнал, запрос к ИИ.
- **Вывод**: просмотр результата.

Статусы прогона: `выполнено` (зелёный), `пропущено` (серый), `ошибка` (красный),
`цикл` (оранжевый). Нода пропускается, если все её входы — `null` от предыдущих нод,
то есть ветка условия не активна.

## Настройки

Кнопка с шестерёнкой на панели открывает окно с разделами: «Прогон», «Файлы»,
«Почта», «Интерфейс», «Вебхук», «Безопасность». Файл — `flowza_settings.json` рядом
с графом (в собранном exe — `Документы\Flowza`).

Глобальные настройки задают значения по умолчанию; параметр в ноде всегда важнее.
Секреты в настройках не хранятся — только имена переменных окружения, откуда их взять.

| Раздел | Что задаёт |
| --- | --- |
| Прогон | пауза между нодами, таймаут, поведение при ошибке, число повторов |
| Файлы | автосохранение, число резервных копий, рабочая папка |
| Почта | SMTP-сервер, порт, пользователь, STARTTLS |
| Интерфейс | тема (тёмная/светлая), шаг сетки |
| Вебхук | приём входящих запросов, переменная с токеном |
| Безопасность | разрешить ли запросы во внутреннюю сеть |

## Расписание

Нода «Расписание» действительно запускает граф по интервалу (1–1440 минут), пока
приложение запущено; отсчёт начинается с момента старта. Срабатывание запускает
весь граф, данные приходят в ноду как `{"event": "schedule"}`.

## Вебхук (вход)

Адрес — `POST /hook/<суффикс>`, где суффикс задан в ноде (пусто — идентификатор ноды).
Тело — JSON-объект, он попадает в ноду как `{"event": "webhook", "body": {...}}`.

```bat
set FLOWZA_WEBHOOK_TOKEN=длинная-случайная-строка
```

Токен передаётся заголовком `X-Flowza-Token` или параметром `?token=`. Если токен
не задан, принимаются только запросы с этого же компьютера. Лимит — 30 запросов в
минуту, тело — до 256 КБ.

## Прогоны: прогресс, отмена, история

Запуск асинхронный: прогресс-бар показывает, сколько нод пройдено, кнопка «Отменить»
останавливает прогон (нода «Задержка» прерывается сразу). Окно истории хранит
последние 50 прогонов: время, источник (вручную / расписание / вебхук), сводка и
кнопка «Открыть» — она показывает результат прошлого прогона. Результаты последних
10 прогонов остаются в памяти, старые доступны только как сводка.

Прогоны идут в очереди: пока один выполняется, следующий ждёт и стартует сам —
расписание и вебхук больше не теряют события. Отменить можно и ждущий прогон:
`POST /api/cancel` с телом `{"run_id": "…"}`, без тела — отменяется текущий.
HTTP-запрос и письмо прерываются кнопкой «Отменить» с задержкой до 5 секунд.

### Письмо (SMTP)

Пароль в графе не хранится: укажите имя переменной окружения, из которой его взять.

```bat
set FLOWZA_SMTP_HOST=smtp.yandex.ru
set FLOWZA_SMTP_PORT=465
set FLOWZA_SMTP_USER=robot@example.ru
set FLOWZA_SMTP_PASSWORD=пароль-приложения
```

Параметры в ноде перекрывают переменные окружения. Порт 465 — SSL, 587 — STARTTLS.

### Вебхук (HTTP)

Реальный запрос `POST`/`PUT`/`GET` с JSON-телом. Таймаут 1–120 с, ответ сервера
(до 2000 символов) попадает в результат ноды.

### Запрос к ИИ

**Заглушка.** Нода подписывает данные промптом и помечает результат `"stub": true`,
но никуда не обращается. Так сделано сознательно: подключение модели требует ключа
и выбора провайдера.

### Файлы и SQLite

Все пути — только внутри рабочей папки (по умолчанию `Документы\Flowza\workspace`):
абсолютные пути, `..`, симлинки и зарезервированные имена Windows отклоняются.
Запись разрешена в `.json`, `.csv`, `.tsv`, `.txt`, `.md`, `.log`, размер — до 5 МБ.
Файлы читаются в utf-8, utf-8-sig, windows-1251 или cp866; CSV выгружается с защитой
от формул Excel.

SQLite: один запрос за вызов, только параметризованный (`?` и JSON-массив параметров),
по умолчанию база открывается только для чтения. `ATTACH`, `DETACH`, `PRAGMA`,
`VACUUM`, `REINDEX` и несколько запросов через `;` запрещены.

### Регулярные выражения

До 500 символов; вложенные квантификаторы вида `(a+)+` отклоняются сразу, а
остальные шаблоны выполняются движком `regex` с таймаутом 2 секунды — шаблон
вроде `(a|aa)+$` на длинной строке получит ошибку вместо зависания.

### Защита

- HTTP-ноды и вебхук наружу: только `http`/`https`, без учётных данных в URL,
  внутренние адреса (localhost, 10.x, 192.168.x, 169.254.x) запрещены, пока не
  включён пункт «Разрешить запросы во внутреннюю сеть».
- Хост резолвится один раз, соединение идёт на проверенный IP: DNS-rebinding
  между проверкой и запросом не проходит. Редиректы проверяются заново.
- Почта: перевод строки в теме или адресе — ошибка (защита от подстановки заголовков).
- Все параметры нод ограничены по длине, JSON — по глубине и числу узлов,
  цикл — 5000 элементов, SQL и CSV — 10 000 строк.
- CSV экранирует формулы (`=`, `+`, `-`, `@`), но не портит числа: `-3` и `-1.5`
  выгружаются как есть.
- API принимает запросы только со своего адреса: чужой `Origin` получает 403.
  При запуске с `--host` вне `127.0.0.1` обязателен токен:

```bat
set FLOWZA_API_TOKEN=длинная-случайная-строка
```

  Тогда запросы к `/api/*` и `/hook/*` из сети требуют заголовок
  `X-Flowza-Token`, иначе — 401.

## Проверки

```bash
python -m unittest discover -s tests -v
node --check flowza/web/app.js
```

90 тестов: движок, граф, реестр нод, настройки, безопасность (обход путей, SSRF
и DNS-rebinding, ReDoS, инъекции), очередь прогонов, планировщик и API.

Интерфейс использует Font Awesome 5 (Solid) — тот же набор, что и qtawesome
(`fa5s.*` → `fas fa-*`). Файлы лежат в `flowza/web/vendor/fa/`, CDN не нужен,
